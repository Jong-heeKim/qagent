## 고객 관점 문제

- 측정 수치가 나와도 좋은지 나쁜지 판단할 기준이 없어 의사결정에 활용하지 못함 (10)
- 개선 사이클이 길어 빠른 반복 개선이 구조적으로 불가능 (9)
- 비기술 직군(PM·기획자·운영자·팀장)이 품질 결과를 직접 확인하거나 측정에 참여할 수 없음 (8)
- 도메인 특화 평가 기준 부재 — 금융·의료·교육·이커머스별 기준이 달라야 하는데 없음 (6)
- 고객 컴플레인이 들어오기 전에 품질 이슈를 사전에 감지하지 못하는 사후 대응 구조 (6)
- 버전별 실험 기록·개선 이력을 추적할 방법이 없어 어떤 변경이 효과가 있었는지 불명 (5)
- 고객사·보안 정책이 다를 때마다 평가 환경을 처음부터 재구성해야 함 (4)
- 규제 기관(금융감독원·식약처 등) 제출용 품질 보고서 포맷이 없어 매번 직접 제작 (3)
- 여러 변수를 동시에 변경하면 개선 원인을 격리하지 못함 (3)
- 업계 경쟁사 대비 품질 수준을 파악할 방법이 전혀 없음 (3)
- 경영진·임원에게 AI 품질을 설명·설득할 언어와 형식이 없음 (3)
- LLM API 비용·응답 시간 문제로 CI/CD 연동이 불가능 (2)

## 기능 제안

- 도메인 특화 평가 템플릿 제공 (금융·의료·교육·이커머스 등) (5)
- 비기술 직군도 직접 사용할 수 있는 직관적 품질 대시보드 (신호등·색상 방식) (4)
- 경영진·임원 보고용 자동 리포트 생성 (수치 해석·업계 비교 내러티브 포함) (3)
- 규제 기관 제출용 자동 품질 보고서 생성 (금융감독원·식약처 포맷) (3)
- 버전별 자동 비교 및 실험 추적 기능 (변경 전후 지표 자동 대조) (3)
- 재사용 가능한 평가 환경 템플릿 (고객사·도메인별 재구성 없이 시작) (2)
- 시계열 히스토리 자동 저장 및 개선 추이 시각화 (2)
- Human-in-the-Loop 평가를 위한 비기술 도메인 전문가용 인터페이스 (의료진·교사 등) (2)
- 경량 평가 모드 (API 비용 절감형 핵심 케이스만 빠르게 검증) (1)
- 실서비스 기반 공개 벤치마크 (학술-실무 연결) (1)
- 비즈니스 KPI 연계 품질 지표 (전환율·이탈률·고객 만족도와 상관관계) (1)
- 개선 요청–검증–결과 확인을 하나의 흐름으로 통합하는 워크플로우 (1)
