## 전반적 의견 취합

| 구분 | 핵심 의견 | 해당 사용자 유형 |
|------|----------|----------------|
| **모니터링** | 문제가 생겨야 알게 되는 사후 대응 구조. 실시간 자동 품질 감지가 없으면 항상 고객 피해가 먼저다 | 전체 공통 |
| **접근성** | 기술 직군만 품질을 볼 수 있는 구조가 가장 큰 문제. PM·기획자·운영자도 직접 확인할 수 있어야 한다 | PM, 기획자, 운영자, 팀장 |
| **해석 지원** | 숫자는 나오는데 좋은 건지 나쁜 건지 모른다. 업계 기준치와 해석 가이드가 없으면 측정이 의미 없다 | 기술직, 비기술직 공통 |
| **도메인 특화** | 의료·금융·교육은 일반 LLM 평가 지표를 그대로 쓸 수 없다. 도메인별 평가 템플릿과 기준이 필요하다 | 의료, 금융, 교육 운영자 |
| **개선 추적** | 개선을 요청하고 효과를 보려면 수주가 걸린다. 개선-검증 사이클이 자동화되지 않으면 빠른 반복이 불가능하다 | 전체 공통 |
| **리포팅** | 경영진이나 규제 기관에 보여줄 표준 보고서 양식이 없어서 매번 처음부터 PPT를 만든다 | 팀장, 운영자, 컨설턴트 |
| **환경 진입** | 환경 구성 자체가 큰 프로젝트. 빠르게 시작할 수 있는 템플릿과 가이드가 있었다면 수일을 아꼈을 것이다 | 주니어, 비기술직 |

## 단계별 핵심 Pain Point 요약

| 단계 | 핵심 Pain Point | 잠재 니즈 |
|------|----------------|----------|
| 품질문제 인식 | 사후 대응, 발생 규모 파악 불가 | 실시간 자동 품질 이상 감지·알림 |
| 측정방법 탐색 | 도구 선택 기준 없음, 도메인 특화 방법 부재 | 도구 비교 가이드, 도메인별 평가 템플릿 |
| 평가환경 구성 | 높은 진입장벽, 비기술 직군 접근 불가 | No-code 평가 환경, 빠른 시작 템플릿 |
| 측정 실행 | 진행 불투명, 수동 평가 확장 불가, 실시간 확인 불가 | 자동화 평가 + Human-in-the-loop 하이브리드 |
| 결과 분석 | 해석 기준 없음, 보고 자동화 없음, 히스토리 미적립 | 벤치마크 비교, 자동 리포팅, 시계열 대시보드 |
| 개선 적용 | 원인 불명, 효과 추적 불가, 사이클 느림 | 버전별 품질 자동 비교, 개선 원인 분석, 빠른 검증 |
